# Compiler process protocol

`merl-compiler` can run a configured executable without giving it database access. The executable reads one JSON request from standard input and writes one JSON response to standard output. Merl caps the response bytes while it reads them, validates the fields, and records the attempt before policy considers any assertion. The first-release evaluator must supply a model-backed executable; Merl does not select a model or read provider credentials for it.

The request has schema `merl.compiler-request/v1`. Its `context` contains the triggering source, a bounded recent source window from the same Issue or conversation, accepted objects at the interpretation basis, and the source observation cutoff. `limits` includes input and output byte caps, a provider-facing output-token cap, assertion and context-request counts, expansion rounds, and a cap on source text. A model wrapper must apply `output_tokens` to its provider call. Merl independently enforces the byte and structural limits when the wrapper responds.

The response has schema `merl.compiler-response/v1`. It may contain `assertions`, `relations`, `context_required`, and `unresolved`. Unknown fields fail validation. Assertions use bounded structural identifiers and cite byte spans in a captured source version. Free-form explanations and copied source prose have no response field. A failure records a stable code such as `output_budget` or `invalid_response`; it leaves no partial assertions.

The request and response have generated JSON Schemas. Run `cargo run -q -p merl-compiler --bin merl-compiler-schema` to print them. The schemas come from the Rust types used by the process adapter, so an external wrapper can validate JSON without maintaining a separate copy of the field list. Merl still checks semantic limits, such as source spans and assertion counts, after decoding.

The authority first records an immutable run intent with the exact rendered context behind an erasable payload reference. The compiler receives owned context bytes and runs without borrowing the store. After it returns, the authority records a separate immutable result with the validated response behind another payload reference. A pending intent remains discoverable after a crash. Repeating a completed run identity with the same context and configuration reuses its outcome. An evaluation run never satisfies live semantic coverage.

For historical evaluation, import sources with `import_fixture_for_causal_replay` into a new project. That import leaves the terminal provider snapshot out of accepted state. Compile each observation in order, supplying the accepted revision reached after earlier observations as the next interpretation basis. An ordinary late compilation uses the basis recorded when its source was captured. If an older capture has no reliable basis, Merl refuses ordinary causal compilation instead of treating today's revision as historical fact.
